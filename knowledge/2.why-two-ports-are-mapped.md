# why two ports are mapped ?

```dockerfile

services:
  jupyter:
    build:
      context: .
    ports:
      - "8888:8888"
      - "4040:4040"
    volumes:
      - ./notebooks:/home/jovyan/work
      - ./data:/home/jovyan/data
      - ./src:/home/jovyan/src


```

They’re forwarding **two different ports from the Docker container to your host machine**:

```text
ports:

- "8888:8888"
- "4040:4040"
```

**8888:8888 — Jupyter:**

This is for the **Jupyter Notebook/Lab server**.

- Container port: **8888**
- Your machine: **localhost:8888**
- You'd typically open: **http://localhost:8888**

Jupyter listens on port 8888 by default.

**4040:4040 — Spark UI:**

Port **4040** is commonly used by **Apache Spark** for its web UI.

If you're running Spark from your Jupyter notebooks, Spark's driver typically starts a UI at:

```text
http://localhost:4040
```

It lets you inspect things like:

- Spark jobs
- Stages
- Tasks
- Executors
- SQL queries
- Storage/cache information

**Why do you need both?**

Because they are **two separate web services running inside the same container**:

```text
Your browser
│
├── localhost:8888 ──► Docker container:8888 ──► Jupyter
│
└── localhost:4040 ──► Docker container:4040 ──► Spark UI
```

So if you only care about Jupyter and don't need the Spark UI, you can remove:

```text
- "4040:4040"
```

_Note: Spark UI port 4040 is not necessarily always active. It only appears when a Spark application is running, and Spark may use 4041, 4042, etc. if 4040 is already occupied._
