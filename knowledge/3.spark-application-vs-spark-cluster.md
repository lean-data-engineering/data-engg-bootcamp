# spark application vs spark cluster

**A Spark cluster is the infrastructure that provides computing resources. A Spark application is the program that uses those resources to process data.**

For development/learning, you can use Spark in a **single-machine (local) mode**, where the cluster and your application are effectively running on the same machine.

## 1. What is a Spark Cluster?

A **Spark cluster** is a collection of computing resources used to run Spark applications.

In a production/distributed environment, it might look like:

```text
                    Spark Cluster
                         │
              ┌──────────┴──────────┐
              │                     │
          Driver                 Workers
                                    │
                         ┌──────────┼──────────┐
                         │          │          │
                      Executor   Executor   Executor
```

The cluster provides the resources needed to process large amounts of data.

### Main components

#### 1. Driver

- Coordinates a Spark application.
- Creates the execution plan.
- Communicates with executors.
- Usually there is one driver per Spark application.

#### 2. Executors

- Run the actual tasks.
- Process data.
- Store intermediate/cache data.
- Usually run on worker machines in a distributed cluster.

#### 3. Cluster manager

In a distributed deployment, something needs to manage the available machines/resources. Examples include:

- Spark Standalone
- YARN
- Kubernetes

So a more complete picture is:

```text
                  Cluster Manager
                        │
                        ▼
                   Spark Cluster
              ┌─────────┴─────────┐
              │                   │
            Worker              Worker
              │                   │
           Executors           Executors
```

## 2. What are we using for development/learning?

This is the important part for [**Jupyter + Docker setup**](./1-set-up-pyspark-apache-spark-jupyter-lab.md).

You generally don't need multiple physical machines or a distributed cluster when learning Spark.

You can run Spark in **local mode**.

For example:

```python
spark = SparkSession.builder \
    .appName("LearningSpark") \
    .master("local[*]") \
    .getOrCreate()

```

### `local[*]` means

Run Spark locally on this machine and use the available CPU cores.

```text
                One Docker Container
               /                    \
              /                      \
       JupyterLab                   Spark
          :8888                       │
                                      │
                                 Local Mode
                                      │
                            ┌─────────┴─────────┐
                            │                   │
                          Driver          Local Executors
```

There are no **separate worker machines here**.

Everything is running on the same machine/container.

## 3. What is a Spark Application?

A **Spark application\*** is a particular _program/workload_ that you run using Spark.

For example:

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .appName("SalesAnalysis") \
    .master("local[*]") \
    .getOrCreate()

df = spark.read.csv("/home/jovyan/data/sales.csv")

df.groupBy("product").count().show()
```

This is a Spark application called:

```text
SalesAnalysis
```

Conceptually:

```text
Spark Application
│
├── Driver
│
└── Executors
```

In local mode, these components run on the **same machine** rather than being distributed across multiple machines.

## 4. Spark Cluster vs Spark Application

The distinction is:

```text
SPARK CLUSTER
    │
    │ provides computing resources
    │
    ▼
SPARK APPLICATION
    │
    ├── Driver
    │
    └── Executors
          │
          └── Execute tasks
```

Think of it like this:

| **Concept**           | **Meaning**                                                |
| --------------------- | ---------------------------------------------------------- |
| **Spark Cluster**     | Computing infrastructure/resources                         |
| **Cluster Manager**   | Manages resources in a distributed deployment              |
| **Driver**            | Coordinates one Spark application                          |
| **Executor**          | Executes tasks for a Spark application                     |
| **Spark Application** | Your actual Spark program/workload                         |
| **Spark UI**          | Web UI for monitoring a Spark application                  |
| **JupyterLab**        | Environment where you're writing/running your PySpark code |

## 5. Where does Jupyter fit?

Jupyter isn't the Spark cluster.

Instead:

```text
                    JupyterLab
                       │
                Notebook / Python
                       │
                       ▼
                PySpark / Spark API
                       │
                       ▼
                Spark Application
                       │
                 ┌─────┴─────┐
                 │           │
               Driver     Executors
```

Your notebook is simply **where you're writing and executing the Python code that creates/uses the Spark application**.

## 6. What about your Docker Compose?

You have:

```dockerfile
services:
  jupyter:
    build:
      context: .
    ports:
      - "8888:8888"
      - "4040:4040"
    volumes:
      - ./notebooks:/home/jovyan/work
      - ./data:/home/jovyan/data
      - ./src:/home/jovyan/src
```

This gives you:

```text
                         Docker Container
            ┌──────────────────────────────────────────────┐
            │                                              │
            │  JupyterLab                                  │
            │     │                                        │
            │     │ Notebook                               │
            │     ▼                                        │
            │  PySpark                                     │
            │     │                                        │
            │     ▼                                        │
            │  Spark Application                           │
            │     │                                        │
            │     ├── Driver                               │
            │     └── Executors                            │
            │                                              │
            │  Spark UI :4040                              │
            │                                              │
            └──────────────────────────────────────────────┘
                      ▲                       ▲
                      │                       │
               localhost:8888           localhost:4040
```

Therefore:

```text
- "8888:8888"
```

means:

> Expose JupyterLab to your host.

And:

```text
- "4040:4040"
```

means:

> Expose the Spark application's web UI to your host.

## 7. What does "local Spark cluster" mean?

You may hear people say:

> "I'm running a Spark cluster locally."

This can be confusing.

In your learning environment, you are using Spark local mode, not a real multi-machine distributed cluster.

For example:

```text
             Your Laptop
                  │
            Docker Container
                  │
       ┌──────────┴──────────┐
       │                     │
   JupyterLab               Spark
                              │
                           local[*]
                              │
                       Same machine's CPUs
```

You don't have:

```text
Laptop
   │
   ├── Master machine
   │
   ├── Worker machine 1
   │
   ├── Worker machine 2
   │
   └── Worker machine 3

```

That's a **distributed Spark cluster**.

For learning, local mode is much simpler and is usually what you want.

## 8. Then why does Spark have Driver and Executors in local mode?

Because Spark maintains the same basic programming/execution model.

In a distributed cluster:

```text
Machine 1
└── Driver

Machine 2
└── Executor

Machine 3
└── Executor

Machine 4
└── Executor
```

In local mode:

```text
One machine
└── Spark application
     ├── Driver
     └── Local execution
```

So the difference is primarily **where the components run**, not the fundamental Spark programming model.

## 9. What happens if you have two notebooks?

Suppose:

```text
JupyterLab
│
├── Notebook 1
│     └── Spark Application A
│
└── Notebook 2
      └── Spark Application B
```

You can have two Spark applications running at the same time.

```text
              Same machine
                   │
       ┌───────────┴───────────┐
       │                       │
 Application A           Application B
       │                       │
    Driver                  Driver
       │                       │
    Executor                Executor
       │                       │
   Spark UI :4040          Spark UI :4041
```

The second application may use **`4041`** because the first application is already using **`4040`**.

Your Docker mapping:

```text
- "4040:4040"
```

only exposes port **`4040`**.

So you could see Application A's UI from your host, but Application B's UI on `4041` would not be accessible from the host unless you also publish that port.

**This does not prevent Application B from running**. It only prevents you from accessing its UI through that host port.

## 10. The complete mental model

For your learning environment, remember this:

```text
                         YOUR MACHINE
                              │
                       Docker Container
                              │
                 ┌────────────┴────────────┐
                 │                         │
             JupyterLab                  Spark
               :8888                       │
                 │                         │
             Notebook                      │
                 │                         │
              PySpark                      │
                 │                         │
                 ▼                         │
          Spark Application ◄──────────────┘
                 │
          ┌──────┴──────┐
          │             │
        Driver       Executors
          │             │
          └──────┬──────┘
                 │
             Spark UI
               :4040
```

And in a **real distributed environment**, the Spark application can use resources across multiple machines:

```text
                    Cluster Manager
                          │
                          ▼
                  Distributed Cluster
              ┌───────────┴───────────┐
              │                       │
           Worker 1                Worker 2
              │                       │
           Executor                Executor
              │                       │
              └───────────┬───────────┘
                          │
                     Application
                       Driver
```

The key sentence to remember

> **A Spark application is the workload; a Spark cluster is the computing infrastructure used to run that workload. For learning, you can run Spark in local mode on one machine, so you don't need a multi-machine Spark cluster**.

And your JupyterLab is simply the **development environment** from which you create and interact with Spark applications.
